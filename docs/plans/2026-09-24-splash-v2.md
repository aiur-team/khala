# Splash v2 Aiur branding and feature grid

## Goal Capsule

Refresh the public Khala splash with the established Aiur/Archon visual language while preserving its exact agent prompt, local-only assets, security policy, responsive behavior, and accessible controls.

Authority is the current ticket, then the existing landing behavior and repository checks. Stop if the reference assets cannot be traced to an Aiur-owned source or if the change requires relaxing the deployed CSP.

---

## Product Contract

### Summary

The splash should identify Khala as an Aiur product, explain its six core capabilities quickly, and feel visually related to aiur.team and archon.aiur.team.

### Problem Frame

The current page has no real Aiur logo or favicon, spreads the product story across long sections, and uses a background fade and feature layout that do not match the current Aiur sites.

### Requirements

- R1. Vendor the Archon Aiur logo and favicon family locally, add the Archon announcement banner and `built with Aiur` footer copy, and record immutable provenance in `apps/web/src/brand/SOURCES.md`.
- R2. Keep the exact hero prompt, copy interaction, Docs link, theme toggle, CSP compatibility, bundled fonts, and white-on-`#1f57c4` button treatment.
- R3. Replace the old content sections with six ordered, concise feature cards using decorative inline SVG icons.
- R4. Place `Encrypted chat for humans and their agents.` above the cards, and `Hailing frequencies open.` below them with `open` highlighted accessibly.
- R5. Fade the diagonal field toward the bottom using Aiur's linear CSS mask pattern, preserve visible focus styles and semantic headings, and collapse cards to one column without horizontal overflow at 390px.
- R6. Extend static and browser coverage for content, asset resolution, ordering, responsive layout, theme behavior, and prompt copying.

### Scope Boundaries

- No external asset, font, script, or stylesheet requests.
- No product capability implementation; this change only describes existing or explicitly tagged future behavior.
- No changes to the application shell or sibling Aiur/Archon repositories.

### Sources

- `aiur-team/aiur@0972f02977ecc77fbcce4ae30cae80aa2c879a18`: `website/index.html` and `website/src/styles.css` for the feature grid and bottom-fading field.
- `aiur-team/archon@1c3e8c01aa88e25aa9c12c7fb6e4756b159e94f7`: `site/index.html`, `site/assets/aiur-logo.png`, and favicon files for branding, banner, and footer treatment.

## Planning Contract

- KTD1. Copy the exact Archon-owned binary assets into the landing public directory, where Vite emits them as same-origin root-relative files, and document source commit, blob, and local checksum.
- KTD2. Use static semantic HTML for the feature section and inline stroke SVGs modeled on Aiur's cards. JavaScript remains limited to the existing theme/copy behavior plus an Archon-style announcement banner: visible unless previously dismissed, hidden before first paint after dismissal, and still dismissible when storage is blocked.
- KTD3. Adapt Aiur's three-column borderless feature grid to Khala's tokens, switching to two columns on tablets and one at 440px. Use a visually hidden H2 so the supplied subtext stays the visible introduction while the section remains navigable by heading. Replace the stale hero CTA with Aiur's animated scroll cue.
- KTD4. Replace the current radial mask with Aiur's linear bottom fade on an extended pseudo-element; no canvas or new runtime animation is needed for this static line field.

## Implementation Units

### U1. Vendor and document Aiur identity assets

- **Goal:** Make the logo and favicon family local, traceable, and emitted by the existing splash build.
- **Requirements:** R1, R2.
- **Files:** `apps/web/src/landing/public/assets/aiur-logo.png`, `apps/web/src/landing/public/favicon.ico`, `apps/web/src/landing/public/favicon-16x16.png`, `apps/web/src/landing/public/favicon-32x32.png`, `apps/web/src/landing/public/apple-touch-icon.png`, `apps/web/src/brand/SOURCES.md`.
- **Test scenarios:** HTML declares the local favicon links; the production preview serves each linked icon successfully; no external origin is introduced.
- **Verification:** Checksums and source blobs in `SOURCES.md` match the copied files.

### U2. Recompose splash content and styling

- **Goal:** Deliver the branded hero, banner, six-card grid, concise copy, bottom fade, footer, and responsive states.
- **Requirements:** R1-R5.
- **Files:** `apps/web/src/landing/index.html`, `apps/web/src/landing/landing.css`, `apps/web/src/landing/main.ts`.
- **Test scenarios:** Card titles render in the required order; Listening modes names `steer`, `sync` as the default, and `async`; supplied subtext is exact and the highlighted word meets contrast; legacy sections are absent; 390px has one card column and no overflow; light/dark controls remain accessible. - **Verification:** Inspect production-built light/dark pages at desktop and 390px and save four screenshots for the PR.

### U3. Lock the surface with automated checks

- **Goal:** Prevent regressions in copy, assets, layout, accessibility, and interaction.
- **Requirements:** R2-R6.
- **Files:** `apps/web/src/landing/landing.test.ts`, `apps/web/src/landing/landing.browser.spec.ts`.
- **Test scenarios:** Assert ordered titles and the pinned Listening modes copy, exact subtext and highlight, removed sections, favicon responses, footer text, same-origin resources, prompt clipboard behavior, banner dismissal states, button colors, theme persistence, and phone overflow/card-column behavior.
- **Verification:** All web package gates and the production browser test pass.

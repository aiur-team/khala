# Khala conversations

Signed-in owners open `/conversations` to see joined, encrypted rooms from their active Matrix session. Selecting a room opens its canonical `/channels/<encoded roomId>` link without leaving the shell. The compact list searches only locally authorized rooms and shows a preview, time, and unread state when available. The single top navigation row shows the conversation title, verified participant names as they arrive, an honest connection state, and sharing. A name from the authenticated participant directory appears while encrypted name history is still being checked; an unverified connection reads unavailable. Click the title to inspect participants, then select your agent to see its listening mode and owner controls. Other people's agents show identity and presence only. Enter sends a message, Shift+Enter inserts a line break, and the empty composer has no placeholder. If the session, owner, device generation, or room membership changes, the view clears and checks access again before showing messages. The channel view keeps the existing encrypted timeline, retry, recovery, review, and owner controls. Each member can use the share icon in the top row to copy their own invitation link for their agent or another person. The header does not display the link. A person joining from someone else's link gets their own link after joining; giving the first person's link to their agent prompts them to use their own. An agent's request still needs approval. Joining does not make earlier history readable.

When an agent connector is offline, review and owner controls reads show unavailable until the connector answers. The browser retries at a bounded rate, and a later answer restores the current view. An unavailable read does not approve a release or change owner controls.

**Delete conversation** is in the title disclosure when the current owner has the close-channel capability. Its separate confirmation explains that closure stops new messages, removes the channel from this owner's view, and requests cleanup on this owner's devices. Delivered copies cannot be recalled, and service retention and global erasure are not promised. Cancel leaves the channel intact; a partial or unknown outcome must be inspected rather than treated as deletion.

The presentational boundary is `apps/web/src/ui/conversation/index.ts`. It exports `ConversationLayout`, `ConversationList`, `ChatThread`, `ChatMessage`, `ChatComposer`, and `ParticipantDetail`, plus the `ConversationSummary` prop type. The populated fixture and production timeline both render messages through `ChatMessage`; the UI directory owns the avatar and bubble styling. These components accept display data and callbacks; Matrix, auth, routing, and Khala contract types stay in `apps/web/src/composition/human/`. A later shared Aiur package can move the UI directory and its token based CSS, then replace the local import paths without moving the Matrix adapter.

For visual review, run the web Vite server and open `/conversation-fixture.html`. Its fixed populated list, message thread, composer, and optional detail pane are independent of live data. Check dark and light at widths 1440, 1100, 900, 760, and 390 pixels. Live proof requires a signed-in Matrix owner with an admitted encrypted room: open `/conversations`, send from another admitted device, then verify live arrival, send/retry, reload, pagination, and browser back navigation on the canonical channel link.

The public home page also mounts these presentational components in an interactive example pane between the hero and feature grid. Its labeled conversations, participants, and messages are fixed local examples; typing adds a bubble only to the current page session. It never joins a room or sends through Matrix. The link below the pane opens the authenticated app.

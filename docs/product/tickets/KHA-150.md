## Outcome and acceptance

`codex queue` is added as route A and selected per binding in `inspect`; the proven app-server route stays as route B. If the payload cannot travel on stdin, route A carries notification only and route B carries the bytes.

## Amends or supersedes

Amends KHA-118. Nothing proven by KHA-104 is removed: the at-most-one-queue-add-per-release rule, the writer-lock trust model and the reconcile-while-queued behaviour are preserved verbatim.

## Exclusive proposed write surface

- `packages/harnesses/src/codex/`

## Boundaries

- Sibling implementation directories, shared contract rewrites, and new product scope
- Alternative backend or crypto protocol implementation
- Released bytes never travel in process arguments, environment variables, receipts, endpoints, errors or logs
- No route may read pending, unreleased content; the connector-gated airlock in P04 is unchanged

## Contract and verification handoff

Consumes reviewed contract subpaths; defines only its owned module API. Dependencies supply reviewed contracts or actual wiring prerequisites; test each component against injected ports until its named integration owner supplies live composition. Keep unit tests adjacent to owned code.

At merge: own tests and affected contracts pass on current base, and `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm typecheck` and `pnpm test` all pass. Real proof belongs to the named integration/evidence owner in the repository layout; component tests are not deferred until then. A capability record may claim `support: "tested"` only when its `evidenceRef` names a document that exists under `docs/evidence/`.

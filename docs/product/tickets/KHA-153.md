## Outcome and acceptance

One owner runtime selects an adapter from the capability record, falls back to the skill path when none is usable, records the selection so a restart cannot silently change route, and exposes agent presence to the channel page. Agent onboarding is one documented command per harness.

## Amends or supersedes

Amends KHA-133 and consumes issue #42. KHA-133 composes bootstrap, storage, subscription, dispatch and a single fail-closed Claude adapter; this ticket replaces that single adapter with capability-driven selection and adds the presence port KHA-152 needs. Issue #42 is consumed here in full: `BootstrapOperationStore` and the Ed25519 signer key are persisted on the connector ledger, the device identity is bound before any other write (or bootstrap rows are kept out of `holdsState`) with a mid-bootstrap restart tested, and revocation is terminal per `bindingId` with re-bootstrap minting a new one.

## Contract and verification handoff

Consumes reviewed contract subpaths; defines only its owned module API. Dependencies supply reviewed contracts or actual wiring prerequisites; test each component against injected ports until its named integration owner supplies live composition. Keep unit tests adjacent to owned code.

At merge: own tests and affected contracts pass on current base, and `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm typecheck` and `pnpm test` all pass. Real proof belongs to the named integration/evidence owner in the repository layout; component tests are not deferred until then. A capability record may claim `support: "tested"` only when its `evidenceRef` names a document that exists under `docs/evidence/`.

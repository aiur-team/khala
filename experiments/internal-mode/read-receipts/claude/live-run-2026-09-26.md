# Claude native receipt run, 2026-09-26

This disposable run exercised the merged receipt build at `d389c79` with Claude Code 2.1.283 on Linux x64. It is evidence for the receipt candidate, not for the final application build. The installed Khala plugin ran in an interactive Claude TUI under normal trust, using the owner's experimental `steer` grant and route `claude-interactive-hooks`. The Executor started the PTY through an assistant tool with isolated `HOME` and XDG directories, as decision 43 permits for this acceptance. The person-started field remains false because that separate provenance was not observed. Receipt support is proven only for this exact version and route; steer and other mode delivery remain experimental.

The package installed in the isolated fixture was the locally packed merged build. Setup was applied only after its dry-run showed paths inside the fixture. The first dry-run exposed an omitted XDG data override and was not applied; the corrected setup kept all writes in the fixture. Existing normal Claude login was reused only in that isolated home. No global Claude or Khala profile was edited.

## Observed cases

| Contract case | Result | Evidence boundary |
| --- | --- | --- |
| Native binding | Passed | Installed plugin requested access, owner approved, and a native tool call reported an active binding. |
| Shared batch and framing | Passed | Native Stop and PostToolUse hook output carried framed untrusted content. The visible TUI capture had no token line. |
| Idle delivery | Passed at the next turn | Owner message waited while the TUI was idle, then appeared at the next native Stop boundary. Independent idle wake was not observed or advertised. |
| Busy delivery | Passed | Two owner messages entered during native tool work and appeared at PostToolUse boundaries. |
| Next-call acknowledgement | Passed | After hook delivery the owner receipt count stayed at zero until a native `khala_status` call, then became one. Subsequent native calls raised the count to three after busy delivery, four after reconnect, and five after rejoin. All five facts were `agent_acknowledged`. |
| No later call | Passed | Owner receipt count remained fixed after delivery until the next authenticated native call. A hook event alone did not record a receipt. |
| Reconnect | Passed | `claude --continue` resumed the same native session; an outstanding owner batch arrived and a subsequent native call recorded its receipt. |
| Stop | Passed | Owner Stop revoked the binding. The Claude TUI stayed alive; its next Khala call was refused as unbound, no later message was delivered to the revoked binding, and receipt count stayed four. |
| Rejoin after Stop | Passed | A fresh owner approval activated a new binding. Native next-call acknowledgement moved owner receipt count from four to five. |
| Wrong token | Passed, direct diagnostic only | A direct local acknowledgement request returned HTTP 400; it did not consume the pending batch or add a receipt. |
| Wrong binding | Passed, direct diagnostic only | A direct local acknowledgement request returned HTTP 401; pending batch and receipt count were unchanged. |
| Wrong generation | Passed, direct diagnostic only | A direct local acknowledgement request returned HTTP 401; pending batch and receipt count were unchanged. |
| Missing token | Passed, direct diagnostic only | Against a batch pending from the native Stop hook, omitting the token returned HTTP 400. The pending batch stayed byte-for-byte unchanged and owner receipts stayed at zero. |
| Duplicate token | Passed, direct diagnostic only | After the native next call recorded one receipt, replaying its exact token and release/event claims returned HTTP 200 `duplicate`; owner receipts stayed at one. |

The wrong-identity, missing-token, and duplicate probes used local diagnostic scripts and the real server acknowledgement route. They are server-boundary tests, not evidence that a native plugin exposed or submitted malformed values. In the fresh continuation, a native Stop hook created one pending batch. Missing-token refusal left it intact, the next native `khala_status` call recorded one `agent_acknowledged` fact, and the fact's release and event IDs matched that pending batch. Exact-token replay then returned `duplicate` without another fact.

The raw TUI captures, Claude session journal, owner session material, and server output remain outside this repository in a private fixture directory. They are mode `0600` and are not part of this report. The retained `evidence.json` contains only non-secret labels and results. No token bytes, reusable token digest, channel message, or canary marker is retained here.
